# Public edit-sequence follow-up

Observed 2026-09-28 UTC. This is a source and schema probe, not an accepted training shard. No model call, training run, GPU allocation, or live editor change occurred. The frozen plan-11 data gate and its 0 accepted labels remain unchanged.

## Finding

The most promising new *bank of ordered edits* is [NVIDIA Open-SWE-Traces](https://huggingface.co/datasets/nvidia/Open-SWE-Traces), pinned at dataset revision `f8fb5b3d2c787f85f8a00f5fe04fe3f1a11088ef`. Its [v1.0 distribution](https://huggingface.co/datasets/nvidia/Open-SWE-Traces/blob/f8fb5b3d2c787f85f8a00f5fe04fe3f1a11088ef/data_distribution.md) reports 151,219 agent trajectories, including 34,343 Python, 32,988 Go, 27,045 TypeScript, and 17,299 Rust trajectories. These are trajectory counts, not distinct editable states or accepted one-line labels. The card provides repository names, a repository license field, ordered messages, tool calls, and a trajectory-level resolved flag. It declares CC BY 4.0 for the dataset and describes the underlying task repositories as MIT, Apache-2.0, or BSD licensed. File-level notices and source commits still need verification.

I fetched only the first 20 rows of the `v1.0/sweagent` viewer API, 5,364,798 response bytes. The rows span 19 repository names: 8 Python, 3 Go, 3 TypeScript, 3 JavaScript, 2 Rust, and 1 PHP. Seven have `resolved=1`, nine `resolved=0`, and four `resolved=-1`. The first row contains 97 ordered messages and 48 messages with tool calls. This fixed prefix is not a random sample, and no file mutation was reconstructed. It proves the schema is accessible at a bounded size, not that it yields clean one-line labels. The dataset's tool calls can contain arbitrary shell code. Treat them as data; do not execute them to extract edits.

I then froze [a separate structural probe plan](public_trace_probe_plan.json), SHA-256 `c8e0c07ba29dc7eebe1234f5571d236e6f53245ed6d8867380133a9c9cbd9f79`, before fetching five later blocks. The [100-row result](public_trace_probe_results.json) used 28,594,303 response bytes, below its 40 MiB cap. Those rows span 86 repository names and contain 695 `str_replace_editor` replacement calls, but only **24 calls in 12 trajectories** have both `old_str` and `new_str` confined to one physical line. None has a reconstructed pre-state or an independently accepted label. The 12/100 trajectory yield is structural only, from fixed offsets rather than a random sample. It is far below the existing 60/100 accepted-case expansion gate even before replay, source-file licensing, and inferability checks. This narrow direct-extraction route should not be scaled as the 20K source.

The main mismatch is task evidence. An agent sees an issue statement and can make many tool-driven changes. The one-line editor predictor will see current code and recent edits, but generally not that issue statement, agent thoughts, or future tests. A resolved trajectory does not make each internal step a useful or inferable next-edit target. Every retained step must be labeled as an **agent-authored, issue-conditioned source** and must pass a separate blind check using only the student's actual input. Do not call these human keystrokes or human acceptance.

## Decision and possible next test

The direct single-line `str_replace_editor` route fails the declared expansion gate. Do not count the 24 calls as training examples or run a larger scrape under plan 11. A later, separately frozen proposal could test whether multi-line tool replacements contain recoverable independent one-line steps, but it needs a new denominator and cannot invent intermediate edit order.

If such a new pilot is warranted, first inventory file sizes, source repositories per language, and generator subsets under the pinned revision. Reserve repository-disjoint development and final-test groups before sampling. Select at most 100 candidate trajectories, up to 25 per target language and no more than two per repository, with a 100 MiB transfer cap. Record every selected ID and rejection.

Extract only explicit, parseable file mutations. Reconstruct their pre-state from a pinned public source revision and prior accepted deltas; do not execute arbitrary trace shell commands or treat the final patch as a transcript of intermediate states. Reject rows whose state cannot be reconstructed exactly, whose file license is unresolved, or whose action is outside `single-line-edit-v1`. Build the student prompt without the issue text, future test output, target diff, or agent reasoning. Blind review inferability and an independent objective check must still pass. Use the prior 60/100 overall and 10/language acceptance gate for a larger expansion. If the pilot fails, preserve its measured yield and stop; do not relabel agent success as a clean next-edit example.

This route may fail because most agent tools produce bulk edits or because the issue statement explains the change. That is an empirical question. At present the accepted train/development/test counts remain **0/0/0**, and no 20K training bank has been found.

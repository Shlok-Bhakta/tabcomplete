# Fixed teacher calibration suite

Suite `independent-synthetic-teacher-calibration-v1` uses the frozen `single-line-edit-v1` contract, suite revision 3. The [fixture](calibration_cases.json) contains 16 original synthetic development cases, four each in Python, TypeScript, Rust, and Go. Within each language there is one replacement, keep, insertion, and deletion. Four same-source pairs differ only in visible recent history: the edit member shows a prior sibling identifier suffix change; the keep member shows a latest actual edit that restored the target's unsuffixed identifier. They use the same file identity, target, and source within each pair. The code is original for this calibration and does not use the four Git pilot repositories or TabComplete's sealed corpus.

The [manifest](calibration_manifest.json) fixes the exact fixture SHA-256 `a8d552f75819db2a7f16ec60e30ed08f94cd969b98cb4d64216325b87cfc248e`, every canonical case hash, the case count, language and action balance, and development-only status. Loader `load_calibration_cases(fixture_path, manifest_path)` rejects a mismatched fixture, changed case, non-development row, invalid history, or invalid gold action. Do not modify the fixture after teacher calibration begins; a result-changing correction needs a new plan/suite revision.

## Solver input and scoring

Construct each solver input with `calibration_prompts(cases, q25_tokenizer)`. It exposes only the `single-line-context-v2` serializer's state text, case ID for bookkeeping, and measured input-token count. The prompt contains source, target row, cursor byte column, recent actual edit, and relevant snippets. It excludes `gold_action`, `after_source`, objective specification, mechanism, family, and split. In a local tokenizer check against pinned q25 revision `8123ea2e9354afb7ffcc6c8641d1b2f5ecf18301`, input lengths were 172–220 tokens (median 203), every history item was included, and gold wire plus EOS required 2–18 tokens (median 5.5). The model has a 64-token response cap including EOS.

Use greedy decoding until an actual tokenizer EOS. Preserve raw wire text, actual termination, generated-token count, and provider finish reason. No stop-string or cap cutoff counts as EOS. Pass complete `Prediction` rows to `score_calibration_predictions(cases, predictions)`. It enforces one response per case and reports valid action, explicit termination, edit-required success, keep recall and false edits, action breakdown, and language breakdown. Provider access checks are separate from this quality calibration. No hosted-teacher quality result is claimed by this document.

## Independent checks and controls

All objectives parse the resulting code with the installed tree-sitter grammar and reject syntax errors. Replacement checks derive the required suffix from visible prior edits and require its use at the target while rejecting the old access. Keep checks preserve the target after an explicit recent reversal. Guard insertions require a code condition linked to a visible source comment. Deletion checks require one fewer physical line and exactly one remaining copy of the formerly duplicate statement. They are structural checks, so their success is narrower than full functional correctness; undefined external types and compiler/runtime behavior are outside this 16-case calibration.

CPU controls passed: 16/16 gold actions satisfy their checks; the unchanged source fails all 12 edit-required objectives; a wrong `BROKEN` replacement fails all 16; the always-keep control succeeds on no edit-required cases and recalls all four keep cases. A nonexact but structurally valid Python replacement passes the alternative-valid check. Every before and after source parses without tree-sitter errors. These checks are fixed before teacher quality outputs are read.

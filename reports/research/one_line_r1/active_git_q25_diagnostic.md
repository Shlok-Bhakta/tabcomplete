# Installed q25 on fixed public repeated-edit states

The [v4 frozen plan](active_git_q25_diagnostic_plan_v4.json) sent the nine
previously selected public Git states to the installed adapted q25-coder
Q4_K_M service on crabcake. It used the same compact next-edit prompt shape as
the Neovim plugin, with the cursor at the start of the changed identifier, 80
preceding and 40 later lines, and the synthetic earlier edit represented in
the recent-edit field. The raw source, selected target lines, and model hash
were fixed before this check. This is a narrow transfer diagnostic on
constructed intermediate states, not a test of observed human edit order.

One fixed Python case was built both by the Python evaluator and the installed
Neovim plugin after applying the synthetic earlier edit to a disposable
buffer. Their prompt bytes matched exactly: 5,280 bytes, SHA-256
`72006fc6b845a422ede0d3711370d799a439db71c00f134c98ce51c20f819869`.
This validates the serving prompt construction for that case; the other eight
were generated by the same deterministic builder but were not individually
cross-checked in Neovim.

The [v4 results](active_git_q25_diagnostic_results_v4.json) contain nine
requests, with actual tokenizer lengths from 830 to 1,169 input tokens. All
nine returned a valid compact `R` action with observed EOS termination; **zero
of nine** replacement suffixes matched the committed target. Eight outputs
were empty replacements, which would delete the editable suffix. The remaining
output was multiline and would be suppressed from the initial automatic
single-line display. Median completion time was 9,934 ms for these serial,
warm-resident, uncached requests. It includes HTTP, prompt processing, and
generation; no per-stage timing or memory sample was captured in this small
diagnostic. It is not the prior short-context cached-action latency or a
distributional editing latency estimate.

The [v1 plan](active_git_q25_diagnostic_plan_v1.json) exited before a result
because the runner read the output cap from the wrong JSON field. The
[v2](active_git_q25_diagnostic_results_v2.json) and
[v3](active_git_q25_diagnostic_results_v3.json) outputs were retained after a
prompt parity check found they omitted one preceding source line. Both used
approximate prompts and also matched zero of nine; v4 is the conclusion-bearing
revision. No fixture, target, model weight, or decoding limit was changed to
rescue those outcomes.

The earlier 1,024/1,024 synthetic held-out result used close relatives of a
16-family training grammar. The new nine-case result shows a concrete transfer
failure on one public repeated-change pattern despite valid serialization.
Nine selected cases cannot establish a general failure rate or rank models.
The sample includes one documentation URL/comment change; its order within the
Git commit is unknown. The model was not adapted on these cases, and no
training label was accepted from them.

The practical next step is still a larger licensed set of observed or
independently reviewable editor transitions with group-disjoint evaluation.
The installed automatic mode remains experimental and applies nothing without
the user's explicit acceptance key. The new optional feedback review event
can qualify later local decisions when actually confirmed, but the current
database has zero confirmed human reviews and personalization training remains
disabled.

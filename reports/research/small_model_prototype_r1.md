## Inference host and service memory

The actual inference machine in these measurements was desktop `crabcake`: AMD Ryzen 5 PRO 3400GE, 4 cores/8 threads, 14.58 GB physical RAM, Vega integrated GPU available but `-ngl 0` forced CPU. Its pinned llama.cpp revision was `f072b103714dfa1eee531f80b24512faf38e3dd2`. The T480s alias timed out, so no T480s performance or installation is claimed. The server used one slot, four threads, Q4_K_M, context 2,304, prompt/cache RAM 128 MiB, context checkpoints 32, batch 256, microbatch 64, and no saved idle-slot snapshots or speculative model. Each candidate loaded alone. Available RAM at the end of each run, CPU thermal samples, full PSS/anonymous/file-backed breakdown, pressure, swap and major-fault counters are recorded in [controlled hardware](small_model_prototype_r1/hardware/crabcake-controlled.json) and [normal-editing hardware](small_model_prototype_r1/hardware/crabcake-normal-editing.json).

The normal-editing process mix contained headless Firefox, two real LazyVim instances on disposable Python/Lua files, and an active Lua language server. Its background processes held about 1.35 GB RSS. It is a reproducible editor workload, not an observed GUI editing session. The two Qwen Q4 files are both about 397 MB, yet q3 retained substantially more anonymous state and peaked near twice q25's RSS. File size alone did not predict resident service memory. Predictor process swap remained zero. Normal-editing windows observed 0–3 system swap-in pages and zero swap-out pages per run, while memory pressure `avg10` stayed at 0.00. Existing nonzero system swap occupancy is not evidence of thrashing. Host RAM and predictor RSS are separate from training memory; the CPU run used no VRAM.

The deterministic replay had 12 editor states at each of two repetitions, covering file open, appends, rejection followed by alternate typing, earlier edits, and switch/return. Fixed source targets were about 512, 1,024, and 2,048 tokens, with actual q25/q3 token ranges 422–424, 857–859, and 1,759–1,761; LFM and P12 ranges differ and are recorded. Backend `timings.cache_n` showed exact token-prefix reuse; it was not inferred from `cache_prompt=true`. Fresh versus cached output tokens were identical in 8/12 q25, 11/12 q3, and 12/12 LFM/P12 states. This is consistent with the pinned server's documented possible numerical differences under altered batching, not a claim of deterministic identity. The separate saved-idle-cache diagnostic showed no meaningful q25 RSS reduction when optional saved idle slots were disabled while preserving active state. ## Next-edit data and protocol

The bounded supervised data has 4,096 distinct synthetic training states, 1,024 development states, and 1,024 separate held-out states grouped by language/action/family. Its train/development/held-out SHA-256 values are in the frozen plan and the private data manifest. Each state includes a reconstructible recent synthetic edit, a current file, cursor and byte region, and one of insertion, replacement, deletion, or defensible no-edit targets. Applying each target reconstructs the generated after-state. No benchmark, sealed personal corpus, employer code, or unrelated later edits entered training. The compact wire format is `N\n` plus EOS for no edit, or `R\n` plus exact replacement text and EOS for edit; an empty replacement is deletion. It maps to the existing v2 canonical action schema. Incomplete or malformed outputs are not repaired or counted as terminated.

The initial 16-case native q25 Q4 evaluator smoke produced 0 terminated compact actions and 0 exact edits; it validates the evaluator path and is too small to estimate next-edit quality. The unadapted causal screening above is likewise not next-edit evidence. The first matched adaptation allocation evaluated 512 unadapted development cases per finalist, then correctly stopped at its 64-state training-only fixture. Both models learned the `R` header, EOS, and deletions, but emitted `R` on every no-edit case. No probe or main pilot ran. The exact loss, token, memory, and fixture outcomes are preserved in [diagnostic-v2.json](small_model_prototype_r1/adaptation/diagnostic-v2.json). The revised disposable [fixture suite](small_model_prototype_r1/adaptation/fixture_suite-v2.json) registers this failure before retry: it adds explicit training-only action cues and balances the `N`/`R` targets, while leaving the main data and frozen development and held-out assignments unchanged. The identical V2 unadapted outputs are reused by [hash-locked baseline record](small_model_prototype_r1/adaptation/v2-baselines.json), avoiding another hour of GPU generation. This diagnostic is implementation evidence, not next-edit quality evidence.

## Collector audit before training readiness

A disposable multilingual repository exercised the existing collector with stubbed rare model responses. The final synthetic session `e022bfdc-1d61-400c-bc98-64ce6e3694ab` has 39 unique events, zero sequence gaps, six requests, three shown proposals, one scripted acceptance, two scripted explicit rejections, three edit deltas including undo, and eight retrievable anchor payloads whose SHA-256 values all matched. Replay reconstructed all three deltas with no unanchored or mismatched events. An interrupted collector request spooled locally and recovered. These are integration checks, not human acceptance or model-quality observations. Earlier synthetic sessions with pre-anchor gaps remain in the collector and are excluded from readiness. The evidence export keeps five-second, thirty-second, and next-save outcomes censored when unobserved; ignoring, stale responses, shadow predictions, timeouts, and explicit rejection remain distinct. There are zero defensible genuine preference pairs. Automatic personalization is disabled. See [feedback verification](small_model_prototype_r1/feedback_verification/live_synthetic.json).

A later personal adaptation would train a separate candidate adapter from a batch of verified feedback, check held-out personal and general regressions, and activate or reject a versioned artifact with rollback. This campaign does not train preferences or mutate the served model during typing pauses.

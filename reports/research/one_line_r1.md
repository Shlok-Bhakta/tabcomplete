## Implementation and evidence

The [contract](../../src/tinycomplete/one_line/contract.py) applies one physical-line keep, replacement, deletion, or insertion byte-exactly across LF, CRLF, EOF, tabs, and Unicode. The [context serializer](../../src/tinycomplete/one_line/context.py) keeps answer-bearing split and mechanism metadata out of prompts. The [evaluation scorer](../../src/tinycomplete/one_line/evaluate.py) separates valid wire output, EOS, edit-required success, keep false edits, and unknown alternative edits. It has independent gold/unchanged controls, development-only display calibration, grouped uncertainty, paired outcomes, and a one-shot final-test claim. These are implementation tests, not model scores.

The [training primitives](../../src/tinycomplete/one_line/train.py) supervise response and real EOS positions only, average target loss within each example and then across examples, and select the causal logits needed for target positions. They enforce token and deadline caps and save full restart state with hashes. A tiny Qwen2 CPU test compared selected-logit gradients and continuous versus save/reload updates; this does not validate q25 CUDA throughput or bitsandbytes. The Kaggle [worker](../../scripts/train_one_line.py) validates the exact pretrained files, dataset manifest, split, source license, action reconstruction, planned tokens, and storage before model load. Its CPU inspection of 64 disposable synthetic rows found 9,570 nonpadding input tokens and 128 supervised target-plus-EOS tokens over two planned updates. No update was run on those rows. The [campaign entry point](../../scripts/run_one_line_campaign.py) checks the frozen plan, live quota, one-job rule, token cap, and cumulative campaign artifact storage.

The untouched q25 foundation was run locally on the frozen 16-case synthetic calibration suite with two CPU threads, FP32 weights, greedy decoding, and the 64-token output cap. It produced **0/16 valid new-contract wires**, with all 16 generations hitting the cap without EOS. This measures serialization under an unseen codec, not underlying code competence. Load time was 1.17 seconds; median generation time was 11.06 seconds per request, and peak observed process RSS was 2,489,987,072 bytes on this CPU test. [Raw baseline results](one_line_r1/evaluations/untouched_q25_calibration.json) preserve per-case outputs and timing. No LR pilot, learning curve, sealed final evaluation, F16 export, Q4 conversion, or laptop sanity measurement occurred. The older four-recipe adapter and live Q4 deployment remain historical controls only.
